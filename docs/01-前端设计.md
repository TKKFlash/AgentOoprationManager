# 前端设计

> 本文件描述已实现的界面结构，与代码保持一致；代码与本文冲突时以代码为准并回改本文。
>
> 第 5 期将讨论室改为对话框布局、新建任务时必填工作目录，目标设计见 [`03-架构设计/06-第5期目标设计.md`](03-架构设计/06-第5期目标设计.md) §13，**待批准，尚未实现**。工作台与仪表盘的设计见本文 §8。

## 1. 技术选型

- React 19 + Vite 8，入口 `apps/web/src/main.tsx`，根组件 `App.tsx`。
- 样式为普通 CSS：`styles.css`（沿用的设计变量与总览页样式）与 `tasks/tasks.css`（任务页样式，通过 `TaskSpace.tsx` 引入）。不使用 UI 框架。
- 不内联样式（`style=` 属性），以兼容生产环境的 CSP（`style-src 'self'`）。

## 2. 路由

哈希路由，由 `route.ts` 解析：

| 哈希 | 页面 | 组件 |
|---|---|---|
| `#overview`（默认） | 总览：本机服务与存储健康状态 | `App.tsx` |
| `#tasks` | 任务空间列表 | `tasks/TaskList.tsx` |
| `#tasks/new` | 新建任务 | `tasks/NewTask.tsx` |
| `#tasks/<id>` | 讨论室 | `tasks/TaskRoom.tsx` |

侧边栏导航保留“总览”与“任务空间”两项；“运行时间线”已并入讨论室，不再单独列出。

## 3. 数据访问

- 所有 HTTP 请求只经 `api.ts`。`request()` 统一设置 `accept`，有请求体时设置 `content-type: application/json`；服务端返回的 `error` 字段直接作为用户可见的错误信息。
- POST 请求由浏览器自动带上同源 `Origin`，满足服务端的 Origin 校验；开发模式下经 Vite 代理访问 `/api`。

## 4. 同步策略

- **任务列表**：每 3 秒轮询 `GET /api/tasks`。
- **讨论室**：`useTaskSnapshot`（位于 `TaskRoom.tsx`）以 `afterSeq` 游标轮询快照：
  - 首次或刷新时游标为 0，获取完整状态（任务、步骤、产物、事件）；
  - 之后只请求新事件，`mergeSnapshot` 按 `seq` 去重追加；步骤与产物每次整体替换；
  - 任务进入终态（`completed`、`cancelled`、`failed`）后停止轮询；非终态每 1.2 秒轮询一次，请求失败时 3 秒后重试。
- 刷新页面不会中断任务，因为任务运行在服务端；页面只是读取已保存的快照。

## 5. 讨论室组成

- 头部：任务目标、协作方式、状态、结论不完整标记、调用计数、验收标准。
- 控制：运行中可暂停或取消；暂停时显示“正在进行的调用结束后，不再开始新步骤”；已暂停可继续。
- 参与者状态条：每位参与者的最近步骤与状态；第一位标注为协调者（协调者模式）或主持收敛（讨论模式）。
- 讨论室（左栏）：已产生输出的步骤显示为发言气泡；失败、超时、取消、跳过的步骤显示为系统提示。
- 动态步骤（右栏）：按序号列出所有计划步骤，含状态、负责人、轮次、耗时、输入摘要与说明。
- 产物：最终结论的完整文本；任务未产生结论时说明原因。
- 事件日志：可折叠，按 `seq` 排列。

## 6. 新建任务表单

- 参与者按选择顺序排列，最多 6 位，至少 2 位；第一位在协调者模式中担任协调者。
- 选择 Codex（只读）时显示提示，并显示可选的只读工作目录；留空则使用服务的专用空目录，不访问项目目录。
- 预算字段的上下限来自 `/api/profiles`，与服务端一致；讨论轮数仅在多轮讨论中可编辑。
- 客户端只做必填与数量的即时提示，最终校验以服务端返回的错误为准。

## 8. 目标设计：工作台与仪表盘（待批准）

> 本节描述第 5 期工作台与第 9 期仪表盘的界面设计。样式使用本项目的普通 CSS，不引入 UI 框架（`AGENT.md` §2）；用户可见文本为中文（`AGENT.md` §6）。

### 8.1 工作台（讨论室）

- **头部**：标题、描述、参与者入口（打开参与者抽屉）、相关任务抽屉、过滤抽屉、更多菜单。
- **参与者状态条**：每个参与者一个芯片，显示头像、标签、协调者标记与状态徽章。
  - 忙碌（思考、调用工具、回复）高亮；沉默与离线显示；空闲不显示。
  - 点击芯片展开近况浮层：最近步骤、沉默次数、用量与耗时。
  - 忙碌时可“取消当前发言”，仅用户可见，二次确认。该操作只结束当前步骤，任务继续（决策点，见 `06 §13.1`）。
- **消息线程**：用户消息靠右，参与者消息靠左，系统消息单独样式；长内容折叠，标签字段（结论、依据、分歧、风险）可单独展开。权限请求卡片在引入写入能力后嵌入线程。
- **输入框**：自动增高（上限与普通输入框一致）；Enter 发送，Shift+Enter 换行。
  - `@` 补全：`@all` 置顶；↑↓ 选择，Enter 或 Tab 选中，Esc 关闭。
  - 存在活跃参与者时，`@all` 发送前需确认，避免误触发全员发言。
- **新建任务**：选择需要工作目录的参与者（如 Codex）时，工作目录必填，即时校验；按适配器显示只读方式与注意事项（`03-架构设计/07-智能体接入规划.md` §3.2）。

### 8.2 仪表盘（第 9 期）

- **统计卡片**：运行中、已完成、结论不完整的任务数；调用已用与上限；失败与超时数。
- **最近事件**：按时间列出事件（`events`），可按任务筛选。
- **参与者表现**：平均耗时、失败率、沉默率、被跳过次数；进度条按同组最大值归一化。
- **数据来源**：汇总数据由服务端计算（只读汇总接口），前端不做聚合；进行中的任务可读，且不影响运行中的任务。
- **动效**：只保留必要过渡，并遵守 `prefers-reduced-motion`。

### 8.3 差异化方向（第 9 期，待确认）

1. 检查点时间线：每个屏障一个节点，可回放，可从此处分叉。
2. 预算与成本视图：调用预算、用量与花费，按参与者与步骤展示，标出预算耗尽的位置。
3. 标签化结论：结论、依据、分歧、风险分栏查看，支持按字段复制。
4. 只读边界可视化：每个参与者显示生效的只读方式与工作目录。
5. 降级结论解释：列出失败步骤、被截断或裁剪的内容、结论不完整的原因。
