## 1. 数据库（schema v2）

版本记录于 `app_meta.schema_version`；启动时追加迁移（见 `04-开发运维/02-数据库与迁移.md`）。所有表为 `STRICT`。

**app_meta**（v1 起）
- `key TEXT PRIMARY KEY`，`value TEXT NOT NULL`。键：`schema_version`、`last_started_at`。

**tasks**（v2）

| 列 | 类型 | 约束 / 说明 |
|---|---|---|
| `id` | TEXT | 主键（UUID） |
| `goal` | TEXT | NOT NULL |
| `acceptance_criteria` | TEXT | NOT NULL；JSON 数组 |
| `mode` | TEXT | NOT NULL；`coordinator` \| `discussion` |
| `status` | TEXT | NOT NULL；见 §2 |
| `participant_ids` | TEXT | NOT NULL；JSON 数组，顺序即发言顺序 |
| `budget_json` | TEXT | NOT NULL；`{maxTotalCalls, maxRounds, perCallTimeoutMs}` |
| `working_directory` | TEXT | 可空 |
| `config_snapshot_json` | TEXT | NOT NULL；创建时的配置摘要 |
| `degraded` | INTEGER | NOT NULL，默认 0；0/1 |
| `stop_reason` | TEXT | 可空 |
| `calls_used` | INTEGER | NOT NULL，默认 0 |
| `created_at` / `updated_at` | TEXT | NOT NULL；UTC ISO 8601 |

索引：`tasks_created(created_at)`。

**steps**（v2）

| 列 | 类型 | 约束 / 说明 |
|---|---|---|
| `id` | TEXT | 主键 |
| `task_id` | TEXT | NOT NULL；外键 `tasks(id)`，`ON DELETE CASCADE` |
| `ordinal` | INTEGER | NOT NULL；任务内展示顺序 |
| `kind` | TEXT | NOT NULL；见 §2 |
| `title` | TEXT | NOT NULL |
| `participant_id` | TEXT | NOT NULL |
| `status` | TEXT | NOT NULL；见 §2 |
| `input_summary` | TEXT | NOT NULL；分工或输入摘要 |
| `output_body` | TEXT | 可空；完整输出 |
| `note` | TEXT | 可空；失败、超时、取消或跳过的说明 |
| `round` | INTEGER | 可空；讨论轮次 |
| `started_at` / `finished_at` | TEXT | 可空 |
| `duration_ms` | INTEGER | 可空 |

索引：唯一索引 `steps_task_ordinal(task_id, ordinal)`。

**artifacts**（v2）

| 列 | 类型 | 约束 / 说明 |
|---|---|---|
| `id` | TEXT | 主键 |
| `task_id` | TEXT | NOT NULL；外键，`ON DELETE CASCADE` |
| `step_id` | TEXT | NOT NULL；外键 `steps(id)`，`ON DELETE CASCADE` |
| `title` | TEXT | NOT NULL（当前为“最终结论”） |
| `body` | TEXT | NOT NULL |
| `created_at` | TEXT | NOT NULL |

索引：`artifacts_task(task_id)`。

**events**（v2）

| 列 | 类型 | 约束 / 说明 |
|---|---|---|
| `id` | TEXT | 主键，格式 `<taskId>:<seq>` |
| `task_id` | TEXT | NOT NULL；外键，`ON DELETE CASCADE` |
| `seq` | INTEGER | NOT NULL；任务内从 1 递增 |
| `type` | TEXT | NOT NULL；见 §2 |
| `at` | TEXT | NOT NULL |
| `message` | TEXT | NOT NULL；用户可见的中文说明 |
| `step_id` / `participant_id` | TEXT | 可空 |
| `detail_json` | TEXT | 可空；如 `{callsUsed, maxTotalCalls}`、`{durationMs}` |

索引：唯一索引 `events_task_seq(task_id, seq)`。

数据库连接设置：`busy_timeout = 5000`；`foreign_keys = ON`；文件数据库使用 `journal_mode = WAL`。

## 4. HTTP API

所有路由位于 `/api`，由 `task-routes.ts` 注册。写请求须通过 Host 与 Origin 校验（见 `04-安全与数据边界.md`）。

| 方法 | 路径 | 请求 | 成功 | 错误 |
|---|---|---|---|---|
| GET | `/api/health` | — | 200 `{status, storage, storageStatus, schemaVersion}` | 503 |
| GET | `/api/profiles` | — | 200 `{profiles, modes, budget, participantLimits, textLimits}` | — |
| GET | `/api/tasks` | — | 200 `{tasks: TaskSummary[]}`（最多 100 条，按创建时间倒序） | — |
| POST | `/api/tasks` | 见下方 | 201 `{id, status}` | 400 `{error}` |
| GET | `/api/tasks/:id?afterSeq=n` | `afterSeq` 为非负整数，默认 0 | 200 `TaskSnapshot` | 400、404 |
| POST | `/api/tasks/:id/pause` | — | 200 `{id, status}` | 404、409 |
| POST | `/api/tasks/:id/resume` | — | 200 `{id, status}` | 404、409 |
| POST | `/api/tasks/:id/cancel` | — | 202 `{id, status}` | 404、409 |

`POST /api/tasks` 请求体：`goal`（必填）、`acceptanceCriteria`（可选，字符串数组）、`mode`（必填）、`participantIds`（必填，2–6 个且互不重复，须为已知参与者）、`budget`（可选，各字段缺省时用默认值）、`workingDirectory`（可选，须为已存在的绝对路径）。

409 的情形：暂停仅对运行中任务有效；继续仅对暂停中任务有效；取消仅对运行中或暂停中任务有效。

## 5. 不变量（INV）

| 编号 | 不变量 |
|---|---|
| INV-1 | 每次任务或步骤状态变更，与其对应事件在同一事务中写入 |
| INV-2 | 任务内事件的 `seq` 从 1 连续递增，且唯一 |
| INV-3 | 适配器调用在开始时计数；失败、超时、取消同样占用预算 |
| INV-4 | 非最终步骤执行前，`calls_used < maxTotalCalls - 1`；综合与收敛执行前，`calls_used < maxTotalCalls` |
| INV-5 | 暂停只在步骤边界生效，不中止正在进行的调用 |
| INV-6 | 超时与取消通过同一 `AbortSignal` 传递；超时由引擎判定，适配器不计时 |
| INV-7 | 协调者模式中，工作参与者的输入不包含任何其他参与者的发言 |
| INV-8 | 讨论模式中，每位发言者的摘录不超过 `EXCERPT_LIMIT`，且不包含其本人的发言 |
| INV-9 | 综合或收敛只在存在成功输出时执行；否则跳过，任务以“没有产生最终结论”结束 |
| INV-10 | 终态任务不接受暂停、继续或取消 |
| INV-11 | 服务关闭时，先中止运行中的任务并等待其写入终态，再关闭数据库 |
| INV-12 | 服务启动时，排队、运行或暂停中的任务一律标记为失败；该操作幂等，不续跑 |
| INV-13 | 数据库版本高于构建支持的版本时拒绝启动，不降级 |
| INV-14 | 迁移只追加：不删除已有表或列 |
| INV-15 | 只读适配器（codex-cli）的沙箱固定为 `read-only`，且不经 shell 启动 |
| INV-16 | 用户可见的错误消息不包含内部异常消息、stderr 或凭据 |
