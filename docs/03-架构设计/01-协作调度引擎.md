# 协作调度引擎

> 本文描述已实现的调度规则。编码时以代码为准；与代码冲突时回改本文。数据库字段与事件类型见 `03-实现事实清单.md`。

## 1. 状态机

**任务状态**：`queued`（创建后立即过渡）→ `running` ⇄ `paused` → `completed` | `cancelled` | `failed`。

**步骤状态**：`pending` → `running` → `succeeded` | `failed` | `timed_out` | `cancelled`；或 `pending` → `skipped`（预算不足、无可综合输出、服务停止等）；或 `pending` → `cancelled`（用户取消）。

终态任务不再接受暂停、继续或取消（返回 409）。

## 2. 计划

任务创建时一次性生成全部计划步骤并落库为待执行，界面从第一刻起就能显示完整时间线。

- **协调者分工**：`brief`（协调者）→ `dispatch`×n（每位工作参与者一步）→ `synthesize`（协调者）。n 为参与者数减一。
- **多轮讨论**：对 `r = 1 … maxRounds`，每位参与者一步 `discuss(r, p)`；最后一步 `converge`，由第一位参与者执行。

## 3. 协作模式行为

### 3.1 协调者分工

1. **拆解**：协调者收到的指令列出全部工作参与者名称，并要求每人一行 `- 参与者名：分工内容`。
2. **解析**：只接受与参与者名称完全匹配的行；同一参与者只取第一行。
   - 解析不到任何分工：全部改用默认分工，并记录 `plan.adjusted`（“分工格式无法识别”）。
   - 拆解步骤本身失败或被跳过：同样改用默认分工，并记录 `plan.adjusted`（“分工步骤未产生结果”）。
   - 缺失某位参与者的分工：只对该参与者使用默认分工。
3. **执行**：每位工作参与者收到自己的分工与共享约束，**不收到任何其他参与者的发言**。分工摘录写入步骤的输入摘要。
4. **综合**：至少一位工作参与者成功，才执行综合。综合输入为各成功工作参与者输出的摘录（按工作参与者顺序）。成功输出即为最终结论（产物）。
5. **无可综合输出**：综合步骤跳过，任务以“没有产生最终结论”结束。

### 3.2 多轮讨论

1. **发言**：每位参与者的输入是其他参与者的最新摘录（每人至多一条，且只包括已发过言的人）。
2. **指令**：第 1 轮要求独立分析；第 2 轮起要求阅读摘录并说明同意或不同意之处。
3. **收敛**：收敛步骤由第一位参与者执行，输入为所有参与者的最新摘录。收敛成功即为最终结论。
4. **无可收敛输出**：若没有任何参与者成功发言，收敛跳过，任务以“没有产生最终结论”结束。

## 4. 预算

- **计数时机**：调用开始时计数（`calls_used` 加一）。失败、超时、被取消的调用同样占用额度。
- **保留额度**：非最终步骤（拆解、工作参与者、讨论发言）要求 `calls_used < maxTotalCalls - 1`，为综合或收敛保留 1 次。综合与收敛要求 `calls_used < maxTotalCalls`。
- **不足时**：步骤标记为 `skipped`，备注“调用预算不足，未执行”。第一次跳过时写入 `budget.exhausted` 事件，并把任务标记为结论不完整（`degraded`）。
- 预算上下限见 `03-实现事实清单.md` §3。

## 5. 暂停、继续、取消与超时

| 操作 | 条件 | 行为 |
|---|---|---|
| 暂停 | 任务运行中 | 任务变为暂停并写入 `task.paused`；**正在进行的调用不被打断**，之后的步骤在边界处等待 |
| 继续 | 任务暂停中 | 任务恢复运行并写入 `task.resumed`；唤醒等待中的循环 |
| 取消 | 任务运行中或暂停中 | 中止进行中的调用；该步骤标记为 `cancelled`（备注“用户取消，调用已停止”）；其余待执行步骤标记为 `cancelled`；任务结束为 `cancelled`，原因“用户取消” |
| 超时 | 单次调用超过 `perCallTimeoutMs` | 引擎中止该调用；步骤标记为 `timed_out`（备注“超过 N 秒未完成，已停止调用”）；任务继续 |

- 超时与取消都通过同一个 `AbortSignal` 传给适配器；引擎根据是否触发超时计时器来区分两者。超时的判定优先于其他结果，即使适配器稍后返回了内容。
- 取消的响应时间取决于适配器是否及时响应信号。`mock` 立即响应；Codex 适配器结束进程树后返回。

## 6. 步骤结果判定

| 条件 | 步骤状态 |
|---|---|
| 超时计时器触发 | `timed_out` |
| 适配器抛出 `AdapterError`，种类为 `cancelled`，且是我方发起的中止 | `cancelled`（服务停止时为 `failed`） |
| 适配器抛出 `AdapterError`，种类为 `timed_out` | `timed_out` |
| 其他 `AdapterError` | `failed`（备注为错误消息） |
| 其他异常 | `failed`（备注“内部错误，调用未完成”；不暴露异常消息） |
| 返回内容为空白 | `failed`（备注“上游返回内容为空”） |
| 返回非空内容 | `succeeded` |

`failed` 与 `timed_out` 会使任务进入结论不完整状态；`cancelled` 不影响降级标记，因为任务整体已取消。

## 7. 任务收尾

运行循环结束后统一收尾（`finalize`）：

1. **服务停止**：任务 `failed`，原因“服务停止，任务未完成”。
2. **用户取消**：任务 `cancelled`，原因“用户取消”。
3. **已有产物**：任务 `completed`；若存在失败、超时或跳过，则标记为结论不完整。
4. **无产物**：任务 `failed`，原因“没有产生最终结论”。

收尾时仍为待执行的步骤被关闭：取消时为 `cancelled`（“任务已取消，未执行”），其余为 `skipped`（服务停止时备注“服务停止，未执行”，否则备注“前序步骤未能继续，未执行”）。

## 8. 失败与恢复

- **步骤失败不中止任务**：失败只降级结论，后续步骤照常执行。
- **运行循环异常**：所有进行中的步骤标记为失败，待执行步骤标记为跳过，任务标记为 `failed`（原因“内部错误，任务已停止”）。异常本身只记录错误名。
- **服务关闭**：先对所有运行中的任务发出“服务停止”的中止，并等待循环写完终态，再关闭数据库。
- **服务启动**：处于排队、运行或暂停状态的任务标记为 `failed`（原因“服务重启导致任务中断”）；其进行中的步骤标记为失败，待执行步骤标记为跳过。该操作幂等。续跑未实现。

## 9. 摘录与交接

- 摘录上限 800 字符（`EXCERPT_LIMIT`）；超出截断并加省略号。
- 交接简报只包含：任务目标、本次分工、角色、固定约束（“仅基于本简报作答”）与验收标准、已确认事实（空）、证据（空）、摘录、轮次、交付格式。
- 完整输出只用于讨论室显示与产物审阅，不进入其他参与者的简报。

## 10. 并发与事务

- 每个状态变更与其事件在一个事务中写入；事务不可嵌套。
- 同一进程内可同时运行多个任务，各自独立的循环；当前没有全局并发上限（见未决问题）。
- 事件序号 `seq` 在任务内单调递增，由数据库约束保证唯一。

## 11. 事件映射

| 时机 | 事件类型 |
|---|---|
| 创建 | `task.created` |
| 开始运行 | `task.started` |
| 暂停 / 继续 | `task.paused` / `task.resumed` |
| 步骤开始 | `step.started` |
| 步骤结束 | `step.succeeded` / `step.failed` / `step.timed_out` / `step.cancelled` |
| 产物生成 | `artifact.created` |
| 预算不足（首次） | `budget.exhausted` |
| 计划调整 | `plan.adjusted` |
| 任务结束 | `task.completed` / `task.cancelled` / `task.failed` |
