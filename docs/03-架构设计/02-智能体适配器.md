# 智能体适配器

> 本文描述适配器契约、已实现的两个适配器，以及接入新智能体的规则。
>
> **第 5 期目标变化**（输出契约与标签、能力声明新增 `requiresWorkspace`、`maxConcurrency`、`reportsUsage`、用量持久化、参与者身份规则）见 [`06-第5期目标设计.md`](06-第5期目标设计.md) §3、§2.3、§6.4、§12，**待批准，尚未实现**。
>
> **现状缺口**：`usage` 由适配器返回，但编排器未保存；超时强制执行尚未实现（见 `01-协作调度引擎.md` 已知缺陷）。

## 1. 契约

定义于 `packages/shared/src/contracts.ts`：

```text
AgentAdapter
  id: string
  capabilities: AdapterCapabilities
  invoke(request: AdapterInvokeRequest): Promise<AdapterInvokeResult>

AdapterInvokeRequest
  packet: HandoffPacket        交接简报（见 §3）
  signal: AbortSignal          中止信号：超时或用户取消时触发
  workingDirectory?: string    只读工作目录；未设置时由适配器使用其默认目录

AdapterInvokeResult
  output: string               最终答复文本
  upstreamEventCount?: number  仅用于审计
  usage?: { inputTokens?, outputTokens? }

AdapterError(kind, message)    kind ∈ { failed, timed_out, cancelled }
```

规则：

- 适配器必须尊重 `signal`，尽快停止工作，并以 `AdapterError` 结束。
- 适配器**不自行计时**；超时由引擎判定并触发中止。
- 适配器不把上游原始事件作为公共接口；只返回最终答复文本。
- 错误消息面向用户，不得包含凭据或上游的诊断输出。

## 2. 能力声明

`AdapterCapabilities`（只有实测过的能力才为 `true`）：

| 字段 | 含义 |
|---|---|
| `transport` | `in-process`（进程内）或 `subprocess-stdio`（本机子进程 stdio） |
| `supportsStreaming` | 是否支持流式输出（当前均为 `false`） |
| `supportsPersistentSession` | 是否维持持久会话（当前均为 `false`） |
| `supportsCancel` | 是否能响应中止 |
| `supportsWorkingDirectory` | 是否接受工作目录 |
| `supportsSandboxModes` | 是否有沙箱模式 |
| `requiresApprovalBridge` | 是否需要外部审批桥接（为 `true` 的适配器不得启用） |
| `requiresInstalledOptionalDependencies` | 是否需要额外安装依赖 |
| `trustedControllerOnly` | 是否只能由本机受信控制器以 stdio 启动，禁止网络暴露 |

## 3. 交接简报（HandoffPacket）

| 字段 | 内容 |
|---|---|
| `taskGoal` | 任务目标 |
| `assignment` | 本次调用被要求完成的事 |
| `participantRole` | 参与者的角色用途说明 |
| `constraints` | 固定约束“仅基于本简报作答…” + 验收标准（每条以“验收标准：”开头） |
| `confirmedFacts` | 用户确认的事实；当前恒为空（入口未建立） |
| `evidence` | 按需证据；当前恒为空（入口未建立） |
| `digest` | 其他参与者的摘录（见调度引擎 §9） |
| `round` | 讨论轮次（协调者模式为空） |
| `deliverableFormat` | 交付格式要求 |

## 4. mock 适配器（默认）

- 位置：`packages/agent-adapters/src/mock.ts`。不发起任何模型调用，不访问网络。
- 默认输出是确定性文本，首行为 `[模拟输出 #n] 角色（第 r 轮）`，用于标识模拟输出。
- 测试接口：`latencyMs`（固定或按调用序号）、`failOnCall`（指定第 n 次调用失败）、`renderOutput`（自定义输出）、`callCount`（已发起的调用数，含失败与取消）。
- 能力：`in-process`，支持取消，不需要工作目录与沙箱。

## 5. codex-cli 适配器（只读）

- 位置：`packages/agent-adapters/src/codex-cli.ts`。
- **命令**：`codex exec --json -s read-only --skip-git-repo-check --ephemeral`，提示词经 stdin 传入（`buildPrompt(packet)`）。沙箱固定为 `read-only`，调用方无法覆盖。
- **进程**：不经 shell；参数以数组传递；`windowsHide`。
- **工作目录**：`request.workingDirectory` 优先；否则使用构造时指定的 `defaultWorkingDirectory`。服务端将其设为数据库旁的空目录 `codex-scratch/`，**不使用项目目录**。两者都没有时直接失败。
- **答复提取**：逐行解析 JSONL，忽略非 JSON 行。最终答复为所有 `item.completed` 且 `item.type === "agent_message"` 的文本，以空行连接；命令执行条目的输出被排除。用量取最后一个 `turn.completed` 的 usage。
- **退出**：退出码非零或答复为空，判定为 `failed`，错误消息只包含退出码与上游事件数量，不包含 stderr。
- **stderr**：读取并丢弃，不对外展示。stdin 写入的 `EPIPE` 被吞掉，结果由退出码判定。
- **中止**：收到信号后结束进程树。Windows 下执行 `taskkill /PID <pid> /T /F`，随后对直接子进程调用 `kill()`；结果为 `cancelled`。

### 5.1 观察到的上游事件（codex-cli 0.155.1，2026-10-10）

`thread.started`、`turn.started`、`item.started`、`item.completed`（`item.type` 为 `agent_message` 或 `command_execution`）、`turn.completed`（含 `usage`）。该结构来自本机实测，上游版本升级后须复核。

### 5.2 尚未验证

- 通过 stdin 传入提示词在真实 codex 上的执行（依据 `codex exec --help` 的文档行为，未实测）。
- 真实 `codex.exe` 进程树在中止后的残留计数（替身脚本测试覆盖了 Node 进程的结束路径）。
- 只读沙箱的强度（本机仅验证了写文件被拒绝）。

## 7. 新增适配器的规则

1. 在 `packages/agent-adapters/src/` 新建实现，并从 `index.ts` 导出。
2. 能力声明只写实测过的能力；未验证的标为 `false`。
3. 遵守 §1 的规则：尊重信号、不自行计时、不暴露上游事件、错误消息不含敏感内容。
4. 不使用 shell；不使用绕过审批或沙箱的开关；工作目录只读，且不得默认指向项目目录。
5. 在 `apps/server/src/profiles.ts` 注册适配器，并在 `BUILT_IN_PROFILES` 中添加档案；默认不得自动启用真实模型。
6. 自动化测试使用替身脚本（参考 `apps/server/test/fixtures/fake-codex.mjs`），不得发起真实模型调用。
7. 更新 `03-实现事实清单.md` 与本文。

## 8. AcpTransport 基座与厂商行为（规划，待批准）

> 计划与门槛见 [`07-智能体接入规划.md`](07-智能体接入规划.md) §3.1、§3.5、§6。

### 8.1 基座职责

- JSON-RPC over stdio；初始化、会话建立（有落盘 `sessionId` 时先 resume，失败按 `06 §7.3` 显式处理）。
- 单飞行：同一参与者同一时间只有一个进行中的 prompt。
- 取消：先 `session/cancel` 通知，宽限期后硬停止。
- 审批：只读策略下对意外的 `session/request_permission` 按 `optionId` 自动拒绝。
- 客户端能力只声明 `terminal: false`，不声明 `fs`。

### 8.2 厂商薄壳只承载差异

每个厂商文件只包含：启动命令与可执行路径解析、环境变量钉死（只读策略）、模型值包装、认证预检、已知行为。
