# 系统架构概述

> 本文描述已实现的组件边界、运行时形态与信息流。接口、数据模型、事件与配置的细节见 `03-实现事实清单.md`；调度规则见 `01-协作调度引擎.md`；适配器见 `02-智能体适配器.md`。

## 1. 组件边界

| 目录 | 职责 | 状态 |
|---|---|---|
| `apps/web/` | 界面：总览、任务空间、新建任务、讨论室。只经 HTTP API 与服务端通信 | 已实现 |
| `apps/server/` | 本机服务：Fastify HTTP、调度引擎（进程内任务循环）、SQLite 持久化、生产环境静态资源 | 已实现 |
| `packages/shared/` | 共享契约：类型、常量、适配器错误类 | 已实现 |
| `packages/agent-adapters/` | 适配器实现：`mock`（默认）、`codex-cli`（只读） | 已实现 |

| `tests/` | 跨应用测试 | 未建立（当前测试位于 `apps/server/test/`） |

## 2. 运行时形态

- **单进程**：Fastify 进程内同时运行 HTTP 服务与各任务的运行循环。
- **每个运行中的任务**有一个 `RunControl`（中止信号、暂停门闩）和一个循环 Promise；循环结束后从内存表移除。
- **状态以数据库为准**：内存只保存控制对象，不保存业务状态。重启后所有判断基于 SQLite 中的记录。
- **同步**：前端以游标轮询，服务端不推送。

## 3. 分层

服务端分层与依赖方向见 `AGENT.md` §4。要点：

- 路由只做解析与状态码映射；业务规则在编排器；SQL 只在仓库层；连接与迁移只在数据库模块。
- 适配器只依赖共享契约，不接触数据库。

## 4. 信息流（已实现）

1. 用户经 `POST /api/tasks` 提交任务。输入经 `task-input.ts` 校验，编排器固定配置快照，并在一个事务中写入任务、全部计划步骤（状态为待执行）与 `task.created` 事件。
2. 同一调用内启动运行循环：任务状态变为运行中，写入 `task.started`。
3. 运行循环按协作模式依次执行步骤。每次适配器调用前检查暂停与取消，检查预算，计数并标记开始，调用结束后写入结果。
4. 步骤输出保存在 `steps.output_body`；最终结论保存为产物；所有变化同时写入事件。
5. 界面以 `afterSeq` 游标轮询快照，渲染讨论室、时间线、产物与事件日志。
6. 终态写入后循环结束。服务关闭时先中止运行中的任务并等待终态写入，再关闭数据库。

## 5. 持久化概览

- SQLite（`node:sqlite`）；文件数据库使用 WAL；外键开启；忙等超时 5 秒。
- 表：`app_meta`、`tasks`、`steps`、`artifacts`、`events`（字段与约束见实现事实清单）。
- 迁移按版本追加执行（见 `04-开发运维/02-数据库与迁移.md`）。
