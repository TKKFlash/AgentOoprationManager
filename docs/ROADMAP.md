# 分期路线图与审批门槛

## 推进规则

阶段按序推进。每期开始前确认该期范围与验收口径；完成后汇报产物、验证结果、未决风险和建议，再停止等待用户明确批准。未获批准不得开始下一期、扩展到其他阶段或实施“顺手”功能。

## 第 0 期：目录骨架与项目文档 — 已完成

**目标：**建立项目目录骨架、项目规则、项目说明、阶段路线、架构概述和决策记录。

**验收结果：**目录与文档已创建，自动结构检查通过；未添加应用代码、依赖/构建配置或安装动作。用户本人验证未进行。

## 第 1 期：接入与风险验证 — 已完成（只读调查）

**范围：**只读调查 Codex、Hermes、DSH 的本机路径、可用协议、鉴权/权限及消息和事件能力；核实 DSH `127.0.0.1:3080` 的服务身份与用途；审查 Paseo 协作工作流和架构。未发起模型任务、未安装依赖、未更改任何 agent/profile/服务/凭据配置。

**交付：**
- [`INTEGRATION-RESEARCH.md`](INTEGRATION-RESEARCH.md)：连接候选、权限风险、本机检查及未验证项。
- [`PASEO-COMPARISON.md`](PASEO-COMPARISON.md)：Paseo 模式和职责边界的项目映射。

**验收结果：**报告区分了本机检查事实、源码/官方文档结论与未完成的端到端验证；Paseo 建议未被标成已批准实现决策；无运行时代码和依赖变更。自动 Markdown 链接检查通过；用户本人验证未进行。

**主要结论：**本机 `127.0.0.1:3080` 的监听进程是 `pnpm dsh web`，应视为浏览器 UI 而非已确认的 Agent API。Codex `exec --json` 与 DSH Headless `--json` 可作为结构化 CLI 候选，但真实事件、取消与沙箱尚未端到端验证。Hermes one-shot 会自动绕过审批，ACP 检查因缺少可选依赖失败；DSH ACP 使用不带协议认证的 stdio，须严格控制其受信客户端边界。以上均不构成实施连接器的批准。

本期完成后等待用户明确批准第 2 期；未提前开始应用实现。

## 第 2 期：本机应用底座 — 待批准

**目标：**按已选技术方向搭建 React + Vite 前端、Fastify 本机服务和 SQLite 持久层。

**开始前需锁定：**本机监听及浏览器信任校验、进程生命周期、持久化数据边界和错误处理方案；用户明确批准后方可编码。

**验收标准建议：**本机可启动基础界面与服务；有健康检查及 SQLite 最小读写检查；默认仅监听 loopback；启动、停止和失败路径有说明。最终验收口径待该期获批后确认。

## 第 3 期：协作调度 — 待批准

**目标：**建立可配置 agent 选择、适配器契约，以及协调者分工和多轮讨论两种模式。

**验收标准建议：**先由模拟适配器走通两种模式；展示参与者与调用状态；支持暂停、取消、超时和失败反馈；提供可配置的调用/讨论预算；不默认广播完整历史。实施前锁定具体标准。

## 第 4 期：任务工作台 — 待批准

**目标：**实现讨论室与过程时间线，并根据任务拆分动态显示步骤卡片。

**验收标准建议：**卡片展示步骤、状态、负责人、进展、输入输出与相关产物；阻塞、暂停、失败、完成均可识别；保存的数据可在刷新后恢复。

## 第 5 期：提示词、上下文与记忆 — 待批准

**目标：**管理内置协作/角色提示词版本；固定任务上下文快照，支持按需检索证据及遵循 Flash Vault 规则的记忆协作。

**验收标准建议：**能追溯任务启动时的提示词与上下文版本；更新不改变运行中的任务；用户可查看和纠正共享材料/记忆来源；不复制整个 Vault。

## 第 6 期：受控任务执行 — 待批准

**目标：**按任务授权的目录和动作范围执行工作，并显示过程、产物和文件差异。

**验收标准建议：**默认只读；写入严格限于获批范围；变更来源可追溯；越界、删除、不可逆操作和外部写入暂停并等待人工批准。

## 第 7 期：工作台自我改进 — 待批准

**目标：**支持智能体在隔离工作区提出和验证本工作台的改进，由用户决定是否发布。

**验收标准建议：**结果和差异可审阅；未获批准不发布；切换只影响新任务，运行中的任务保留启动时版本。
