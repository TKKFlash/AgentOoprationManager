# 环境搭建与运行

## 1. 环境

- 操作系统：Windows 11（当前验证环境）。
- Node.js 24 或更高版本；pnpm 12（`package.json` 的 `packageManager` 字段）。
- Codex（可选）：本机已安装 `codex` 命令（已验证版本 codex-cli 0.155.1）。通过用户已配置的网关调用，不需要额外登录。未安装时，选择 Codex 参与者的步骤会以“失败”显示。

## 2. 安装

```bash
pnpm install
```

## 3. 常用命令

| 命令 | 作用 |
|---|---|
| `pnpm dev` | 先编译 `packages/` 下的共享库，然后并行启动服务端（4317）与界面（5173） |
| `pnpm build:libs` | 仅编译 `packages/shared` 与 `packages/agent-adapters` |
| `pnpm build` | 编译共享库，构建服务端与前端 |
| `pnpm typecheck` | 编译共享库后，分别检查服务端与前端的类型 |
| `pnpm test` | 编译共享库与服务端后，运行 `apps/server/test/*.test.ts`（40 项） |
| `pnpm start` | 运行 `apps/server/dist/index.js`（需先 `pnpm build`） |

停止服务：在运行终端按 Ctrl+C。Windows 下当前进程不依赖 SIGTERM 的优雅关闭。

## 4. 端口与地址

- 界面（开发）：`http://127.0.0.1:5173`（Vite，`strictPort`）。
- 服务与 API：`http://127.0.0.1:4317`（生产环境同时提供界面静态文件）。
- 两者均只绑定 `127.0.0.1`。

## 5. 环境变量

| 变量 | 默认 | 说明 |
|---|---|---|
| `PORT` | 4317 | 服务端口。修改后，开发时需同步修改 `apps/web/vite.config.ts` 中 `/api` 的代理目标 |
| `AOM_DATABASE_PATH` | — | 数据库文件的完整路径（优先级最高） |
| `AOM_DATA_DIR` | — | 数据目录；数据库文件名固定为 `agent-operations-manager.sqlite` |
| `NODE_ENV` | — | 设为 `production` 时不允许 5173 来源 |

未设置上述路径变量时，默认数据库位置为：

- Windows：`%LOCALAPPDATA%\AgentOperationsManager\agent-operations-manager.sqlite`；
- 其它系统：`$XDG_DATA_HOME/agent-operations-manager/`，否则 `$HOME/.local/share/agent-operations-manager/`。

Codex 默认工作目录为数据库所在目录下的 `codex-scratch/`。

## 6. 测试

- 服务端测试位于 `apps/server/test/`：
  - `app.test.ts`、`lifecycle.test.ts`：服务启动、绑定、Host/Origin、健康检查、页面服务；
  - `database.test.ts`：schema 版本、迁移、拒绝更新的数据库；
  - `orchestrator.test.ts`：调度引擎（使用模拟适配器）；
  - `tasks-api.test.ts`：HTTP API 与输入校验；
  - `codex-adapter.test.ts`：codex 适配器（使用替身脚本 `fixtures/fake-codex.mjs`，不调用模型）。
  - `draft-database.test.ts`：草稿结构的数据库修复后，完整创建并运行一个任务（回归测试）。
- 自动化测试不发起真实模型调用。

## 7. 故障排查

- **API 全部返回 404（`{"error":"Not found"}`），界面能打开**：通常是旧的服务进程仍占用 4317，新服务绑定失败。访问 `http://127.0.0.1:4317/api/health`：若 `schemaVersion` 与代码不一致（例如 1），即连到了旧进程。用 `Get-NetTCPConnection -State Listen -LocalPort 4317` 找到占用进程，确认其命令行属于本项目后停止，再重新运行 `pnpm dev`。新版启动日志中的 `errorCode` 为 `EADDRINUSE` 即是此原因。
- **端口被占用（其它情形）**：改用其它 `PORT`，并同步修改 `vite.config.ts` 的代理目标。
- **`@aom/shared` 找不到**：先运行 `pnpm build:libs`（`dev`、`build`、`typecheck`、`test` 已包含此步骤）。
- **界面显示“无法连接本机服务”**：确认服务已启动，并检查 `http://127.0.0.1:4317/api/health`。
- **Codex 步骤失败**：确认 `codex` 在 PATH 中，且可在终端手动执行 `codex exec --help`。
- **创建任务失败，错误为 `no column named …`**：本机数据库结构与代码不一致。服务启动时会自动执行迁移；访问 `/api/health`，确认 `schemaVersion` 为代码当前版本（3）。若仍失败，把服务端日志中的错误名与 `errorCode` 发给开发者。
