## 背景

用户报告：`/api/health` 的 `schemaVersion` 为 2，但创建任务返回 502。

排查中，经 5173 代理发送的同一请求实际返回 500，服务端错误为 `table steps has no column named output_body`。用户看到的是 502、我们复现的是 500，两者的差别尚未确认。如果用户仍看到 502，需要其 Network 面板中该请求的状态码与响应内容。

## 根因

- 迁移按版本号执行。数据库记录的版本已是 2，因此 v2 DDL 之后的修改不会再对该数据库生效。
- 用户本机数据库的 v2 表结构来自开发期的草稿 DDL：
  - `steps` 缺少 `output_body`、`note`，保留了未使用的 `output_summary`、`error_message`；
  - `steps_task_ordinal` 为非唯一索引，`tasks_created` 缺失；
  - `artifacts` 没有指向 `steps` 的外键，`steps.participant_id` 可空。
- 测试从未覆盖“版本号已是 2、表结构为草稿”的情形：自动测试使用内存库或新建库。

## 实现内容

- `apps/server/src/database.ts`：
  - `DATABASE_SCHEMA_VERSION` 改为 3；
  - 新增 v3 迁移：为 `steps` 补列 `output_body`、`note`（已有列保留）；把 `steps_task_ordinal` 重建为唯一索引；补建 `tasks_created`；
  - 迁移在一个 `BEGIN IMMEDIATE` 事务内执行，失败则回滚。
- 测试：
  - `test/fixtures/draft-database.ts`：复刻草稿结构；
  - `test/database.test.ts`：新增“修复草稿库”用例，版本断言改为 3；
  - `test/draft-database.test.ts`（新增）：草稿库上完整创建并运行一个协调者任务的回归用例；
  - `test/app.test.ts`：版本断言改为 3。
- 文档：数据库与迁移（版本表、v3 说明、残留差异）、实现事实清单、系统总览、开发进度、环境搭建（测试清单与排查项）。

## 数据与接口变更

- 数据库：schema v2 → v3；`steps` 新增两列；`steps_task_ordinal` 改为唯一索引；新增 `tasks_created` 索引。
- 接口：无变化。`/api/health` 的 `schemaVersion` 现为 3。
- 用户数据：没有删除任何表、列或行。修复前后，四张业务表的行数均为 0。
