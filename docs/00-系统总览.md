# 系统总览

> 本文件描述项目定位、目标、技术栈与范围边界。技术细节见 `03-架构设计/`；当前状态见 `02-项目计划/00-开发进度.md`。

## 1. 定位

AgentOoprationManager（AOM）是**面向个人本机使用的多智能体协作工作台**。

- 用户发布通用需求（研究、写作、分析、代码等），在任务中选择参与者，以协作方式推进。
- 过程可视化：参与者状态、动态步骤时间线、讨论室、产物与事件日志。
- 共享策略：只传递完成子任务所需的简报与裁剪摘录，不默认广播完整对话历史。
- 首版单用户、本机运行；不作为公网 SaaS 或多租户服务。

## 2. 目标

1. 让用户把复杂任务拆给多个参与者，并能看清每一步由谁做、做到哪一步、结果是什么。
2. 支持两种协作方式：**协调者分工**（一人拆解，多人完成，一人综合）与**多轮讨论**（按轮次发言，逐轮修正，最终收敛）。当前为串行执行；第 5 期目标为不同智能体并行、同一智能体串行。
3. 任务过程可暂停、继续、取消；超时、失败与预算耗尽有明确反馈。
4. 刷新页面后，已保存的状态可恢复。当前服务重启后未结束的任务标记为“未完成”且不续跑；第 5 期目标为检查点续跑与分叉。
5. 为后续接入更多智能体（Hermes、DSH 等）保留适配器边界；接入须经调查与批准。
6. **（第 5 期目标）** 工作台以对话框形式呈现：创建任务时由用户指定工作目录；讨论中用户可随时插话、定向补充、调整设置或结束讨论。
7. **（第 5 期目标）** 参与者的输出按字段标签保存，下游按策略选择性注入，而不是整段转发。
8. 设计依据是“参与者是不同的智能体”，而不是同一智能体的多个副本。同一适配器的多个参与者须有不同角色，否则不建议用多方讨论的方式运行。

## 3. 技术栈（定案）

| 层级 | 选型 |
|---|---|
| 语言 | TypeScript（`strict`） |
| 前端 | React 19 + Vite 8 |
| 服务端 | Fastify 5 |
| 存储 | SQLite（Node 内置 `node:sqlite`，实验性） |
| 包管理与构建 | pnpm workspace；`tsc`；`vite build` |
| 测试 | `node:test` + `tsx` |

偏离或保留选型的理由见 `02-项目计划/02-决策记录.md`。

## 4. 核心概念

| 概念 | 含义 | 详见 |
|---|---|---|
| 任务（Task） | 目标、验收标准、协作方式、参与者顺序、调用预算、只读工作目录（可选）、终态 | `03-实现事实清单.md` |
| 参与者（Participant） | 内置档案：名称、角色用途、适配器 | `02-智能体适配器.md` |
| 步骤（Step） | 有序动作：拆解分工、分工执行、讨论发言、综合、收敛 | `01-协作调度引擎.md` |
| 产物（Artifact） | 最终结论 | `01-协作调度引擎.md` |
| 事件（Event） | 按任务递增的 `seq` 日志，用于时间线与增量同步 | `03-实现事实清单.md` |
| 交接简报（HandoffPacket） | 交给单次调用的最小输入 | `02-智能体适配器.md` |

## 5. 范围边界

**已实现（截至第 4 期）**

- 本机服务（仅绑定 `127.0.0.1`）、SQLite 持久化（schema v3）、健康检查。
- 任务 API：创建、列表、快照读取（增量游标）、暂停、继续、取消。
- 调度引擎：两种协作方式、调用预算、超时、失败反馈、取消、暂停、服务关闭与启动恢复。
- 参与者：`mock`（默认，不调用模型）、`codex-cli`（只读沙箱，需显式选择）。
- 界面：总览、任务空间、新建任务、讨论室（讨论内容、动态步骤、参与者状态、产物、事件日志）。

**未实现（待后续批准）**

- 提示词版本管理、上下文快照与记忆沉淀（第 6 期，原第 5 期）。
- 受控文件写入与差异审阅（第 7 期，原第 6 期）。
- 工作台自我改进（第 8 期，原第 7 期）。
- 第 5 期提案（对话式工作台、工作目录设置、标签输出、检查点续跑与分叉）：目标设计见 `03-架构设计/06-第5期目标设计.md`，待批准。
- Hermes、DSH 等接入；浏览器端的用户认证；局域网或公网访问。
- 智能体接入（Claude CLI、DSH headless、Hermes 受限模式）：规划见 `03-架构设计/07-智能体接入规划.md`，待批准。
- 服务重启后的任务续跑；实时推送（当前为轮询）。
