## AI 决定（待用户确认）

以下决定由实施过程作出，完整理由见各阶段基线与开发记录。

- **同步方式（2026-10-10）：**采用轮询 + `seq` 增量，不做推送。这只回答了“实时事件传输方式”的一部分（见开放问题）。
- **协调者模式（2026-10-10）：**第一位参与者担任协调者；分工解析失败时回退为默认分工并记录事件；工作参与者互不可见。
- **讨论模式（2026-10-10）：**每位发言者只接收其他参与者的最新摘录；轮数或预算用尽后由第一位参与者收敛。
- **摘录上限（2026-10-10）：**800 字符；完整输出保存在步骤中。
- **预算（2026-10-10）：**调用开始即计数，失败与超时同样占用；为综合或收敛保留 1 次。预算不足则跳过并标记“结论不完整”。
- **暂停与取消（2026-10-10）：**暂停只在步骤边界生效；取消通过 `AbortSignal` 传递给适配器，Codex 按进程树结束。
- **服务重启（2026-10-10）：**未结束的任务标记为“未完成”，不续跑。
- **内置参与者（2026-10-10）：**默认三位为模拟参与者；Codex 只读参与者须显式选择，默认工作目录为数据库旁的空目录。
- **服务重启（2026-10-10，已被提案取代）：**未结束的任务标记为“未完成”，不续跑。2026-10-12 用户指示需要检查点续跑；提案见 `03-架构设计/06-第5期目标设计.md` §7.5，待批准。
- **并行与屏障（2026-10-12，AI 提议）：** 同轮讨论并行、同轮互不可见；同一适配器并发 1，全局并发 3；屏障处写检查点（06 §6–§7）。
- **同适配器同角色（2026-10-12，AI 提议）：** 拒绝创建（06 §2.3）。
- **硬超时与取消中间态（2026-10-12，AI 提议）：** 引擎强制超时，宽限期 5 秒；新增 `cancelling`、`awaiting_user`、`interrupted` 状态（06 §8–§9）。
- **接入顺序与门槛（2026-10-12，AI 提议）：** Claude CLI → DSH headless → Hermes（受限）；每个适配器按 07 §6 分步批准；真实只读验证逐个批准；Hermes 在审批语义实测前不接入（07 §4.3）。
- **ACP 优先（2026-10-13，AI 提议）：** Claude 与 DSH 的首选传输改为 ACP（持久会话、优雅取消、标准审批协议），headless 作为备选；`@zed-industries/claude-agent-acp@0.23.1` 的依赖引入须用户批准（07 §3.7）。
- **只读钉死方式（2026-10-13，AI 提议）：** DSH 用环境变量 `DSH_PERMISSION_MODE=read-only`（源码已核实，替代未核实的 `--patch`）；只读策略下，意外到达的审批请求自动拒绝，并按 `optionId` 精确应答。
- **沉默、安全阀、写入幂等、唤醒策略（2026-10-13，AI 提议）：** 分别见 `06 §3.4`、`06 §8.4`、`06 §4.6`、`06 §4.5`；安全阀默认 3 个屏障，待确认。
- **工作台与仪表盘设计方式（2026-10-13，AI 提议）：** 交互模式与信息结构按本项目需求设计，用普通 CSS 实现，不引入 UI 框架；仪表盘放在第 9 期（`01-前端设计.md` §8）。

## AI 建议（尚未批准实施）

- 建立通用 adapter 与能力声明；CLI、ACP、HTTP 等按能力选择，不统一假设所有 agent 是 Chat Completions。第 3 期已采用能力声明，但只实现了 `mock` 与 `codex-cli`。
- coordinator 默认定向传递最小 handoff packet；先做可限预算、可取消的分层协作，不启用无限 peer-to-peer mesh。
- 对任务、agent session、run event 分层建模；Profile 记录角色用途，并在任务启动时固定配置版本。第 3 期已固定配置快照，版本化提示词留待第 6 期。
- 默认使用只读权限；写操作需任务级目录与动作授权，服务端实施范围校验并展示变更差异。
- Hermes one-shot 的审批绕过风险须通过受限工具 profile 规避并实测；否则暂不作为可执行型接入。
- 代码并发修改可按需要采用 worktree；对非代码任务不强制创建目录或工作树。

## 开放问题

- 工作台是完整 orchestration host（能创建并管理 provider session），还是首版只包装本机 CLI？如何与用户手动打开的 agent Web UI 分工？
- Codex 参与者的真实端到端任务是否批准？这需要新的真实模型调用。
- 若 DSH Web 需程序化集成，是否存在经官方确认、稳定且可安全授权的外部 API 或 SDK？不直接读取其浏览器 cookie 或 session。
- Hermes 在 ACP optional dependencies 缺失时，是否选用 MCP、TUI gateway，或经用户显式授权安装组件？是否单独启用 API Server 及其 `API_SERVER_KEY`？
- DSH ACP 无传输认证时，进程、stdio、session workspace 与外部 MCP 配置边界如何在本机实现和验证？
- 提示词包来源目录、角色 profile 字段，以及轮数与调用数预算的默认值是否需按模型调整？
- 服务重启后的续跑：用户已指示需要。步骤完整性的保证方案（屏障检查点、重跑未完成调用）见 `03-架构设计/06-第5期目标设计.md` §7，待批准。

- 第 5 期提案的其余待决问题（阶段重排、同轮可见性、插话长度、同角色规则、敏感目录清单、同步方式、归档）见 `03-架构设计/06-第5期目标设计.md` §17。
- 实时事件传输方式（轮询之外是否需要推送），以及断线后的补读策略。

- Claude CLI 的 plan 模式只读强度、`--json-schema` 稳定性；DSH 的只读覆盖配置键；Hermes `chat --oneshot` 的审批行为。以上均待实测（见 `03-架构设计/07-智能体接入规划.md` §2、§4）。
