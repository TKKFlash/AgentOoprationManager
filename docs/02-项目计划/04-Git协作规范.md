# Git 协作规范

> 分支、提交与 PR 的约定。与 `AGENT.md` §9 一致；如有冲突，以 `AGENT.md` 为准并回改本文件。

## 1. 分支

```text
main                              # 历史提交所在分支（早于本规范）
  └─ feat/agent-operations-manager   # 暂定长期开发分支，名称待用户确认
```

- 日常开发在开发分支进行，不为每个任务另开短分支（除非用户要求）。
- **禁止**直接在 `main` 上开发。当前开发分支为 `feat/agent-operations-manager`，自 `main` 切出；名称待用户确认。
- 确认前不向 `main` 提交新改动。

## 2. 提交

格式：

```text
[aom] <type>: <说明>
```

- `type` 取值：`feat` / `fix` / `refactor` / `test` / `docs` / `chore` / `perf`。
- 需要区分到人时可使用 `[<person>][aom] <type>: <说明>`。
- 示例：`[aom] feat: 实现讨论模式的摘录上限`。
- 只提交本次改动涉及的文件，不使用 `git add -A` 盲提。
- 提交前用 `git status` 与 `git diff --stat` 核对改动清单。
- 不提交：数据库文件、运行产物、导出文件、日志、凭据、`codex-scratch/`、构建产物（`dist/`）。

## 3. 合并与同步

- 合并前先确认 `pnpm typecheck`、`pnpm build`、`pnpm test` 全部通过。
- 文档与实现同步：涉及接口、数据模型、事件类型或配置键的改动，须同步更新 `docs/03-架构设计/03-实现事实清单.md` 与对应开发记录。
- 遇到冲突先停下：列出冲突文件，给出处理方案与影响，由用户决定。

## 4. 禁止

- 直接推送到 `main`（或后续开发分支以外的共享分支）。
- 强制推送（`git push --force`），删除共享分支，改写已推送历史。
- 提交凭据、真实业务数据、运行产物。
- 测试未通过即合入。
- 未经用户确认，删除或批量移动已跟踪的文档。
